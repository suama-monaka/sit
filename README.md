# SIT Dashboard

## 初回セットアップ

Windows x64環境でルート直下の `環境構築.bat` を実行します。

```powershell
.\環境構築.bat
```

Node.js v24.18.0、Chrome for Testing 151.0.7922.47、npm依存関係を自動で取得します。利用可能なNode.js 20以上とChrome 151以上が既にある場合、起動時はシステム環境を優先します。

初回は管理者復号キーを2回入力し、`config\admin-public-key.bin`へ公開設定だけを保存します。管理者復号キーそのものは保存しません。

サーバー専用秘密鍵は32バイトの暗号学的乱数として自動生成され、プロジェクト内の `SIT-Dashboard\server-secret.key` に保存されます。このファイルを含めてフォルダをコピーすれば別PCでも同じ秘密鍵を利用できます。秘密鍵はGitの除外対象ですが、平文の重要情報なので、プロジェクトフォルダを第三者や公開ストレージへ共有しないでください。

旧方式の `%LOCALAPPDATA%\SIT-Dashboard\server-secret.dpapi` が現在のWindowsユーザーで復号できる場合、環境構築時に同じ秘密鍵をプロジェクト内へ自動移行します。別PCからコピーしたDPAPIファイルは通常復号できないため、元PCで先に環境構築を実行して `server-secret.key` を生成してからフォルダをコピーしてください。

旧形式DBがある場合は、サーバーを停止した状態で環境構築を実行してください。管理者復号キーを入力すると、すべてのDBを新形式へ一括移行します。移行が完了するまでサーバーは起動を拒否します。

## 起動

```powershell
.\start.bat
```

`start.bat`はプロジェクト内の `SIT-Dashboard\server-secret.key` を読み取り、標準入力でNode.jsへ一度だけ渡します。外部環境変数を使った場合も、Node.jsは暗号化ストレージ初期化直後にその環境変数を削除します。後から起動するChromeへ秘密鍵を引き継ぎません。

## バージョン運用

コード、設定、画面、ドキュメントのいずれかを変更した場合は、必ずアプリのバージョンも更新します。細かな修正や調整では末尾のパッチ番号を1つ上げます（例：`2.16.1`から`2.16.2`）。機能追加ではマイナー番号、互換性を壊す変更ではメジャー番号を上げます。

## Androidアプリ

`android-app`にはSIT DashのAndroid版があります。画面、スタイル、JavaScriptはAPKに内蔵され、サーバーとはHTTPSのJSON APIだけで通信します。既定の接続先は `https://sit.racal.f5.si` です。

Android Keystoreで暗号化したIDとPasswordは、強力な生体認証に成功した後だけ復号されます。初回ログイン後に生体認証を行うと、次回起動時は認証後に自動ログインします。Moodle、Campus Square、出席サイトは許可した大学ドメインだけをアプリ内ブラウザで開き、ログインフォームがある場合は認証済みの資格情報を自動入力します。シラバスはアプリ内表示だけを行い、資格情報は入力しません。

```powershell
cd .\android-app
$env:JAVA_HOME = "..\..\Android\.toolchains\jdk17\jdk-17.0.20.1+1"
.\gradlew.bat assembleDebug
```

ビルドしたAPKはプロジェクト直下の `SIT-Dash-Android-2.19.0-debug.apk` と、サーバー配信用の `releases\android` にコピーされます。同時に `latest.json` が生成され、バージョン、容量、SHA-256が記録されます。

Androidアプリは起動時に `/api/android/update` を確認します。新しいAPKがある場合は自動ダウンロードし、容量とSHA-256を検証してからAndroidのパッケージ更新機能へ渡します。初回は端末設定で「この提供元を許可」を有効にする必要があります。Android 12以降では条件を満たせば確認なしで更新されますが、端末やOSの判断で確認画面が表示された場合はユーザー操作が必要です。

すべての更新APKは、端末にインストール済みのAPKと同じ署名鍵で署名してください。署名鍵が異なるAPKはAndroidが更新を拒否します。現在生成するデバッグAPKは開発・動作確認用です。一般配布では専用の署名鍵を安全に管理したリリースビルドを使用してください。

別の秘密管理基盤を使う場合は、64桁の16進数を `SIT_SERVER_SECRET` 環境変数へ設定できます。この場合はLocalAppDataのDPAPIファイルより環境変数を優先します。

ログイン後のIDとPasswordはブラウザへ保存しません。HttpOnly、SameSite=StrictのセッションCookieを使用し、セッションは30分で失効します。

## 公開

サーバーは `0.0.0.0:4007` で待ち受けます。インターネット公開ではHTTPSリバースプロキシからポート4007へ転送し、`Host`または`X-Forwarded-Host`と`X-Forwarded-Proto: https`を送信してください。

既定の公開Originは `https://sit.racal.f5.si` です。別ドメインを使う場合は、起動前に `SIT_PUBLIC_ORIGIN=https://example.com` の形式で設定します。IDとPasswordを扱うため、平文HTTPで公開しないでください。

## 管理者用DB復号

```powershell
.\Admin\admin-tool.bat
```

User IDと管理者復号キーを入力すると、`Admin\<ID>.decrypted.db`へ平文SQLiteを書き出します。管理者経路はサーバー専用秘密鍵を必要としません。

出力にはID、Password、PasswordのSHA-256、時間割、Moodleコース、課題、出欠、更新日時、エラー情報が含まれます。確認後は平文DBを安全に削除してください。

## 暗号化DB

保存先は `cache\<ID>.db` です。SQLiteイメージ全体をランダムな256ビットデータ鍵とAES-256-GCMで暗号化します。テーブル名、列名、値、ID、Passwordは暗号文から直接読めません。同じ内容を保存しても、毎回新しいデータ鍵、salt、nonceを使うため異なる暗号文になります。

データ鍵には独立した2つの復号経路があります。

- 通常経路：ID、Password、サーバー専用秘密鍵の3要素をscryptとHMAC-SHA-256で結合した鍵
- 管理者経路：管理者復号キーからscryptで導出したP-256秘密鍵

通常経路では、ソースコード、暗号化DB、ID、Passwordを取得されても、サーバー専用秘密鍵がなければ復号できません。管理者経路では、管理者復号キーだけで復号できます。

暗号方式を秘密にする独自暗号は使用しません。方式が公開されても鍵がなければ復号できない標準暗号を使用します。正しい最終復号鍵または管理者復号キーそのものが漏れた場合に復号を防ぐことはできません。

AES-GCM認証タグ、IDと用途を含む追加認証データ、SQLite整合性検査により、間違った鍵、DB改ざん、破損を検出します。

## 秘密鍵の扱い

- 管理者復号キーをコード、BAT、設定ファイル、Gitへ保存しないでください。
- `SIT-Dashboard\server-secret.key`は平文の秘密情報です。Git、メール、チャット、公開ストレージへ保存しないでください。
- フォルダを別PCへ移す場合は、秘密鍵ファイルを含むフォルダ全体を信頼できる方法でコピーしてください。
- 旧形式の`server-secret.dpapi`は生成したWindowsユーザーと通常は同じWindows環境でのみ復号できます。
- サーバー専用秘密鍵を紛失した場合でも管理者復号キーがあればDBを再移行できます。
- 管理者復号キーまで紛失するとDBは復元できません。
- 復号済みDBを残さないでください。
